# 匯款欄位實填版說明｜什麼必須由人填

> 報價單模板裡的匯款表可以自動化複製，但**以下欄位絕不能由 Bot 瞎填或沿用示範字**。沒填實值就寄出報價＝無法收款。

---

## 一、必須由真人填（上架／寄報價前）

| 欄位 | 為什麼必須人填 | 填寫範例格式 | 誰負責 |
|------|----------------|--------------|--------|
| **銀行名稱** | 每人本人類／公司戶不同 | `台新銀行 敦南分行` | 收款戶所有人 |
| **銀行代碼** | 匯款 App 靠代碼辨識 | `812`（三碼） | 同上 |
| **帳號** | 敏感＋唯一；填錯錢進別人戶 | 純數字、含或不含分行碼依該行習慣 | 同上 |
| **戶名** | 須與銀行登記**完全一致**（含限公司戶全名） | `王小明` 或 `○○工作室` | 同上 |
| **匯款後通知管道** | 客戶要知道截圖傳哪 | LINE ID / Email | 接案窗口 |
| **統編（若開發票）** | 開立發票法定資料 | 八碼 | 有登記營業再填 |
| **發票抬頭／載具** | 客戶端資料，成交後才知 | 成交時向甲方要 | 窗口於訂金前確認 |

**禁止：** 把模板裡的「〔例：台新銀行〕」「〔請填入〕」原樣貼給客戶。

---

## 二、可先用占位、成交前再補

| 欄位 | 說明 |
|------|------|
| 街口／Line Pay／信用卡連結 | 沒開金流可整行刪除；有再貼短網址 |
| 乙方統編 | 個人接案未開發票可寫「個人接案，收據另行提供」 |
| 報價單編號後段流水 | 可用日期＋手動流水 `Q-20260909-001` |

---

## 三、絕對不要寫進公開 repo／聊天的東西

- 完整銀行**帳號**（公開 GitHub 只留「見私密 ops／密碼管理器」）  
- 身分證字號、帳戶照片、印鑑  
- 客戶匯款截圖（存私密專案夾，勿 commit）  

**公開倉庫建議寫法：**
```
銀行名稱／代碼／帳號／戶名：見私密檔 `ops/PAYMENT_PRIVATE.md`（不進 git）
或由窗口於正式報價 PDF 填入。
```

---

## 四、實填檢查清單（寄出報價前勾）

- [ ] 銀行名稱含「銀行＋分行」（若該行要求）  
- [ ] 銀行代碼三碼正確（可對一次銀行官網或 App）  
- [ ] 帳號已用**小額測試匯入**或對過存摺／App（至少驗證一次）  
- [ ] 戶名與 App 顯示一字不差（注意空白、英文大小寫、股份有限公司全稱）  
- [ ] 匯款備註規則已寫：`請註明報價單編號 Q-…`  
- [ ] 「匯款後請傳截圖至 ____」已是真實 LINE／Email  
- [ ] 公開網頁／repo **沒有**貼完整帳號  
- [ ] PDF／給客戶的那一份**有**完整帳號  

---

## 五、給生存專家／倉庫的分工建議

| 檔案 | 內容 | 是否進公開 git |
|------|------|----------------|
| `ops/quote-template.md` | 模板＋〔占位〕 | ✅ 可公開 |
| `ops/PAYMENT_PRIVATE.md` | 實填銀行四欄＋通知管道 | ❌ `.gitignore` |
| 給客戶的報價 PDF | 模板＋已實填匯款 | ❌ 僅私密傳送 |

---

## 六、一句話規則

**文案與流程 Bot 可產；銀行四欄（行名、代碼、帳號、戶名）＋通知管道＝只有收款人本人類能填，填完才能寄第一份正式報價。**
